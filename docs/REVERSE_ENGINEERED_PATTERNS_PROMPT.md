# Prompt: encode the proven-campaign DNA as reusable building blocks

Hand this to Claude Code from the repo root. This turns a set of approved, proven-winner Raycon emails into the concrete patterns, boilerplate constants, archetypes, and art-direction presets that the generator and the deterministic brief compiler use, so new copy comes out looking like the winners by construction.

Run `npx tsc --noEmit` after each task. Do not regress recent work (hard-rules gate + checker, variations, reviews/product-card, metrics/UI).

**Relationship to the other specs:** these building blocks are the curated content the `docs/DETERMINISTIC_BRIEF_COMPILER_PROMPT.md` compiler assembles, and they extend `src/lib/prompts/playbooks.ts`. If the compiler is built, wire these into it; if not yet, they still improve the current generator via the reference desk + playbooks.

## Source of truth: what the winners have in common
Seven approved campaigns were reverse-engineered. The repeatable DNA:

**Fixed module skeleton (every email):** logo → hero (headline + tagline + image) → offer-as-CTA button → stacked-case body → soft CTA → feature block (3 USPs OR job-differentiated product cards) → "Looking for something else?" cross-sell → "Greatness guaranteed" trust footer → logo/social/legal.

**Two modules are near-verbatim boilerplate** (never re-improvise them):
- Cross-sell: `Looking for something else? The full collection is 15-50% off during our {occasion} Sale. Find your next great audio upgrade today.` + CTA `Shop the Sale` / `Shop Everything`.
- Footer "Greatness guaranteed": trust badges `FREE U.S. SHIPPING`, `TRY FOR 30 DAYS`, `1-YEAR WARRANTY`, then logo / social / legal.

**Element patterns:**
- Headline: 2 to 4 words, emotional/identity-led, names neither product nor offer ("Never Gets Old", "For The One Who Does It All", "Built For This").
- Tagline: names the product and/or frames the offer ("30% off for 48 hours", "The Everyday Earbuds still got it").
- Offer lives in the CTA button ("GET 15% OFF", "UP TO 50% OFF"); the promo code lives in its own callout pill ("USE CODE: MOTHER"), never inside the CTA.
- Body = stacked case: fact/hook → 2 to 3 concrete specifics → offer drop → soft close ("Some things earn their reputation.").
- USPs: exactly 3, each a 2 to 3 word spec-benefit label + one supporting line.
- Multi-product cards differentiate by JOB, not overlapping specs ("easiest way in / start here", "the most open way to listen", "stay out of the way and still turn heads").

**Five archetypes** (each maps to a skeleton + tone):
1. Evergreen Product Spotlight (reputation/confidence; single product; 3 USPs). e.g. "Never Gets Old".
2. Occasion Gift Guide (multi-product, warm, per-product badges, "for her/them"). e.g. "She's Gonna Love It", "For The One Who Does It All".
3. Category Guide (one category, job-differentiated cards). e.g. "Open For Everyone".
4. Single-Product Flash Sale (deadline-forward, high-energy, one product, code). e.g. "Built For This", "Fitness Open Earbuds 48 hours".
5. Subscriber Exclusive (extra stacked discount, code-gated). e.g. "For The One Who Does It All".

**Art direction by occasion/archetype:** Mother's Day = lavender/cream/floral + gift props; Fitness flash = electric blue + motion + lifestyle-in-action; evergreen = editorial/polaroid, moody. A recurring "three earbuds + RAYCON" divider sits above the footer every time.

## Task 1 — Boilerplate module constants
Create `src/lib/prompts/modules.ts` exporting the two fixed modules as deterministic builders (NOT generated by the model):
- `crossSellModule(occasion?: string)` → the "Looking for something else?" block with the occasion slotted (default: "our current sale"), and the correct CTA (`Shop the Sale` for occasion sales, `Shop Everything` for catalogue).
- `trustFooter()` → the "Greatness guaranteed" three-badge footer (Free U.S. Shipping, Try for 30 Days, 1-Year Warranty). Only assert badges that are true for Raycon; do not invent guarantees.
Insert these programmatically at generation/assembly time so every email ends identically. Add a checker note: these blocks are fixed content and are exempt from the copy scans (they are boilerplate, not fresh copy).

## Task 2 — Proven-pattern reference block
Append a `PATTERNS` section to `data/copy-system.md` (new marked section, read like VOICE/RULES) OR add to the reference desk `data/brand-voice.md`, capturing the element patterns above with 2 to 3 real examples each drawn from the seven winners (headline bank, tagline bank, body stacked-case example, USP triad example, job-differentiated card examples, offer-as-CTA + code-as-callout rule). Keep it tight; these are patterns to match, not prose to admire. Wire it into the generation prompt the same way VOICE is (via `voice.ts` or the assembly in `data.ts`).

## Task 3 — Formalize the five archetypes
Extend `src/lib/prompts/playbooks.ts`: add an `archetype` concept (or map campaign_type + angle → archetype) with, per archetype: the module skeleton (reusing `SECTION_CATALOGUE` types), which element patterns apply, tone, and whether the cross-sell + footer constants are appended. Map the five archetypes above. This becomes the structural spine the deterministic brief compiler reads (see `DETERMINISTIC_BRIEF_COMPILER_PROMPT.md` Task 2/3 — the archetype supplies `structural_notes` and `default_structure`).

## Task 4 — Art-direction presets for Hero Image Direction
Create `src/lib/prompts/art-direction.ts`: `artDirectionPreset({ occasion, archetype, heroProductColorway })` → a 30 to 50 word visual brief seed (palette, props, mood, the "three earbuds + RAYCON" divider above the footer). Presets: Mother's Day (lavender/cream/floral/gift), Fitness flash (electric blue/motion/lifestyle), evergreen (editorial/polaroid/moody), generic sale (warm neutral). The generator uses this as the Hero Image Direction default so design stays on-archetype; it stays a designer brief, no editorial self-commentary (existing hard rule).

## Task 5 — Seed the seven winners as canonical references
Add the seven approved campaigns to the library as structured entries (mirror `data/library/*.md` / the `LibraryCampaign.structured` shape), each tagged with `source: "sent-email-benchmark"`, its archetype, occasion, and products. This makes the scored retrieval (`copy-builder` client) prefer proven winners for similar briefs. Transcribe their copy faithfully from the approved sends (headline, tagline, body, USPs, CTAs, cross-sell). Where a winner says "Classic", keep it in the archived entry (historical) but do NOT let it propagate to new copy (the retired-name hard rule already guards output).

## Task 6 — Verify
- `npx tsc --noEmit` clean.
- Generate one campaign per archetype and confirm: the fixed skeleton appears, the cross-sell + footer are the exact constants (occasion slotted), headline is 2 to 4 words, offer is in the CTA and the code is in a callout (not the CTA), USPs are a 3-item spec-benefit triad, and multi-product cards read as job-differentiated.
- Confirm retrieval surfaces the seeded winners for a matching brief.

## Guardrails
- Boilerplate constants (cross-sell, footer) are inserted, not generated — this is the biggest consistency + token win. Keep them out of the model's hands.
- Patterns guide; the hard rules still gate. Nothing here overrides `data/copy-system.md` RULES (no clichés, no code-in-CTA, em-dash ban, etc.).
- Only real trust badges and real offers. Never invent a guarantee, a discount, or a product name.
